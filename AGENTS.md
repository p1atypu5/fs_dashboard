# Проектный контекст для агентов

## Назначение

Это статичное readonly-зеркало материалов «Последнего слова». Сайт собирается Astro и
публикуется на GitHub Pages; production не использует сервер и не записывает данные.

## Где искать контекст

- `README.md` — быстрый старт, команды и процесс обновления базы.
- `src/content/config.ts` — схема контентных записей.
- `src/lib/queries.ts` — единые правила рабочих выборок; страницы и отчеты не должны
  воспроизводить условия языка или `sourceUrl` самостоятельно.
- `src/lib/` — правила отображения, статистики, языков, имен и тегов.
- `scripts/import-wordpress.mjs` — импорт данных WordPress в Markdown.
- `.github/workflows/update-content.yml` — автоматическая синхронизация контента.
- Локальная папка `faq/`, если она есть, содержит подробные рабочие заметки: цель, архитектуру,
  описание страниц и дорожную карту. Она намеренно игнорируется Git; для поиска по ней
  используйте `rg --no-ignore faq`.

## Источники данных и границы изменений

- WordPress — источник редакционных данных: текстов, тегов, описаний и изображений. Такие
  исправления вносятся в WordPress и приходят при следующем импорте.
- Репозиторий хранит Markdown-копию контента и производные данные сборки. Распознанные язык
  оригинала и дата произнесения остаются только в репозитории и не синхронизируются обратно.
- Не редактируйте `dist/`: это игнорируемый результат сборки.
- Не добавляйте сырые выгрузки WordPress из `data/` в публичный репозиторий.

## Рабочая выборка

- Основной интерфейс сейчас предназначен для русскоязычной рабочей выборки:
  `language === "ru"` и URL источника не содержит `/en/`.
- Англоязычные записи не удалены: они пока скрыты из основной базы и справочников, чтобы не
  смешивать фильтры, имена и служебные данные.
- Справочник тегов строится по русскоязычным записям. Название тега может быть латиничным,
  если это название проекта, медиа или организации; теги англоязычного потока пока не выводятся.

## Проверки

- Перед изменениями контента или логики импорта запускайте подходящие проверки: `npm test`,
  `npm run validate:content` и при необходимости `npm run build`.
- `npm run test:stats` использует snapshot в `scripts/statistics-expectations.json`; обновляйте
  его только при осознанном изменении состава базы или правил подсчета.
- `npm run test:integrity` защищает тексты от массовой порчи. Обновляйте baseline только после
  успешной проверки и осознанного обновления контента.

## Документация

При изменении договоренностей о данных, фильтрах или приоритетах обновляйте соответствующие
рабочие заметки в `faq/`, если они доступны локально. Не считайте их частью публичного артефакта
без отдельного решения владельца проекта.
